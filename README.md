# 国际访学团多语请求与导览接力排程

合成资料放在 `data/corpus.json`，记录类型载于 `data/context.json`。每条记录有独立的 `id`、业务类别 `kind` 及原始文字 `text`。`arrival_order` 表示收件先后，文字内注明的业务发生时间可以早于或晚于收件顺序。`references` 只列来源中已明示的记录关联，空值表示未附明示关联。

使用 Python 3.11 标准库，`materials.load_corpus()` 可读取 UTF-8 原始资料。在项目根目录运行资料校验。

    python3 -m unittest discover -s tests -v

## 接待处理系统（`reception` 包）

持续处理学校提交的团组资料与成员请求，输出可走完的参观安排，并在变化时交接新的服务需求。

| 模块 | 职责 |
| --- | --- |
| `reception/profiles.py` | 按来源提取本人需求；语言、听读、移动、同伴协助与隐私需求分别绑定本人；解析带范围表达，无法确定的细节进入待核实清单 |
| `reception/planning.py` | 场馆服务与口译资源建模、行程排段、约束校验、成员安置判定 |
| `reception/workflow.py` | 按收件顺序持续处理、确认台账、变更交接、协调员/场馆/学校三种角色视图 |

### 关键业务规则的落地方式

- **来源权限**：团组表、本人补充、带队教师说明分别标记来源；教师统一填报（`代填`）对未逐位确认的成年成员不生效，不能替其选择无障碍方式或讲解语言。
- **能力不等同**：中文问路只登记为日常沟通能力，不推断专业讲解能力；能跟随口译与同意汇总发言分别建模，拒绝汇总者在集体交流保留个人提问通道。
- **范围表达**：如"能听普通话，字幕请用英文""只在一楼使用轮椅"，需求只绑定本人明示的活动/楼层；范围不明的细节生成 `PendingQuestion` 交接待员当面核实，系统不推断为全程限制。
- **排程约束**：三类活动分别使用场馆的语言服务、字幕与转场时间；同一口译/讲解资源不能同时服务两个分组；预约窗口（H38）不可拆分、延长或因拆组复制；排段预留场馆间移动时间，并保证全体参加东门集合说明。
- **延误处理**：流动口译设备延误后整体重排（先街区步行、设备送达后英语转述）；拆组方案中拒绝拆组的成员保持"未安置"，不因多数人接受分流而改变状态。
- **发送闸门**：`dispatch_ready()` 仅在行程可行且每位成员的待确认问题均经本人当面核实后为真；此前只在内部给出尚待确认的个人要求。
- **角色可见范围**：协调员可见成员安排、待确认问题与跟进方；场馆只收到本场馆服务所需的语言与移动信息；学校可查行程版本与改派确认。三种对外视图均不含个人需求原话。

### 命令行演示

    python3 -m reception

输出各行程版本的时间线、成员安置状态、交接需求、发送闸门状态、临时拆组评估与场馆视图样例。
